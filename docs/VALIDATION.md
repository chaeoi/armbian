## 主机检查

`./compile.sh check` 检查配置引用、Python/ shell 语法、文档链接、补丁顺序、发布文件集合，
并运行镜像格式和配置保护的单元测试。无需连接设备。
CI 自动运行相同检查；USB 工作流通过官方框架构建完整系统，并校验、上传 `.img.xz` 安装盘。
首次 GitHub 全量运行和实际 USB 刷入完成前，不能记为流程已上机通过。

每次构建保留来源清单、完整 `.config`、编译器信息和 SHA-256。
新构建默认 `tested_boot=false`，即使沿用同一源码与配置也不自动继承旧镜像的实机认证。

## 后续上机验证

在有可用恢复入口且保存已验证包的条件下，验证启动、eMMC、两个 USB 口、正常 SD 卡、
有线与无线双向传输、冷启动和连续普通重启。存储测试需同步并清缓存读回校验，再检查跨重启持久化。
确认无失败服务并读取真实 MMC CRC/超时统计。
硬件测试脚本部分会写测试文件、操作网络或控制器，必须先阅读 `tools/README.md`，不由 CI 执行。
