# 换回旧 SD 卡后的复查 · 2026-11-07

> 历史实测记录。以下工作目录路径相对于当时的项目根目录；原始日志、镜像和设备配置未纳入公开仓库。当前入口见 [测试索引](../VALIDATION.md)。

**同一 Armbian r6、同一卡槽下，旧卡反复初始化失败；用户换回 ACLCE 64 GB 后立即识别，三轮写入与清缓存读回均通过。对照结果更指向旧卡本身或其触点问题。**

用户允许格式化旧卡，但旧卡始终未完成初始化、未生成块设备，因此没有执行格式化或直接扇区写入。本次未读出旧卡 CID，不能将历史 NCard 的身份当成本次实测身份。替换卡的 CID 和 UUID 则已确认与 11 月 6 日通过测试的 ACLCE 卡相同。

## 已取得的证据

| 环境 | 实际结果 |
| --- | --- |
| 初次连接时的海 NAS，`4.4.35_ecoo_81032968` | 卡槽检测到换卡；连续报告 `card never left busy state`、`error -110 whilst initialising SD card`，没有生成 SD 块设备 |
| 恢复后的 Armbian，`7.3.0-rc7-ec6108v9-r6` | 400、300、200、100 kHz 初始化均报告 `Card stuck being busy`，未读出 CID、容量或分区 |
| 只重置 SD 控制器后再次探测 | 同样四档低速初始化失败；没有 `/dev/mmcblk1` |
| 控制器状态快照 | 卡槽检测为有卡、机械写保护未触发；最后保留的响应值为 `0x00ff8000`，就绪位未设置 |
| 用户更换为 ACLCE 64 GB，内核和卡槽保持相同 | 立即正常识别，59.5 GiB、exFAT、4-bit / 25 MHz，CID `03534441434c4345805941242a01129b`、UUID `6802-7F21` |
| 替换卡三轮各 32 MiB 写入、同步和清缓存读回 | 三轮 SHA-256 一致；写入加同步 3.057、3.203、3.068 秒，约 9.99～10.47 MiB/s；每轮冷读约 2.82 秒，约 11.4 MiB/s；CRC/超时计数全部为零 |

失败发生在 SD 初始化阶段，早于分区和文件系统读取。因此，当前故障不能由 FAT/exFAT 文件系统损坏来解释；没有块设备时也无法执行格式化。初始化轮询超时与此前修复的大块数据传输软件超时属于不同阶段，不能混为一谈。

两套内核均出现同类失败，而换卡后同一卡槽立即识别并通过读写，当前证据更指向旧卡本身、触点或插接问题。未用第二个读卡器测试旧卡，因此无法进一步断言是闪存、卡内控制器还是触点故障。

## 替换卡复测

用户随后更换了卡，因此无需继续等待旧卡重新插接。替换卡为原先已通过测试的 ACLCE 64 GB，保留既有文件系统，仅创建独立临时文件进行测试。测试前 `fsck.exfat -n` 显示干净，原有 4 个目录、912 个文件。

三轮测试总计写入、清缓存读回各 96 MiB。最后的 32 MiB 文件经历普通重启后 SHA-256 一致，随后删除。替换卡没有格式化，也没有执行破坏性扇区测试。

重启后仍运行 `7.3.0-rc7-ec6108v9-r6`，启动 ID 为 `d6c860ef-4133-4916-8f0e-4c3d69c969b1`。最终 `fsck.exfat -n` 显示干净，保留原 4 个目录、912 个文件；`/mnt/sdcard` 已自动挂载为可读写，MMC 错误计数全部为零、无失败服务，启动确认及下次启动配置校验通过。

为旧卡准备的 `tools/probe-sd-raw-write.py` 尚未执行。该工具通过显式 CID、精确容量、可移除属性和未挂载状态检查后，在五个位置各写 4 KiB，使用直接 I/O 和同步，再清缓存直接读取，比较新数据与旧数据的摘要。它会损坏原数据，仅适用于明确获准的空卡。
